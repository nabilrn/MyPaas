# MyPaas v0.6.0-rc.2

**Release type:** Prerelease / release-candidate qualification follow-up  
**Target commit:** `4a117768af4b2d3e72581c68f0d4d2ce1c053a4c`

`v0.6.0-rc.2` follows the first real dashboard qualification of the release-aware updater.

## RC1 findings fixed

- The owner-only release notification route now unwraps MyPaas' standard `{ data: ... }` API envelope for `/auth/me` and `/settings`. This fixes the `Status unavailable` state observed during the `v0.6.0-rc.1` test.
- Host updater status is now authoritative for the installed platform revision. API `build_sha` is used only as a fallback, because frontend-only updates intentionally keep the API image on its previous build SHA.
- This prevents a successfully applied frontend-only release from being offered repeatedly after the host updater has advanced the installation.

## Included qualification change

- Administration → General retains the single-separator UI cleanup introduced for the release-notification test.

## Qualification goal

A VM running the fixed dashboard but intentionally left on an older host checkout should detect `v0.6.0-rc.2`, expose the release in the notification bell, queue the manual host updater, advance the host checkout to this exact release target, and report the terminal updater state correctly.

This remains a release candidate for updater qualification, not the final `v0.6.0` release.
