# MyPaaS v0.7.6

**Release type:** Stable patch release  
**Release date:** 2026-10-01  
**Release tag:** `v0.7.6`

`v0.7.6` hardens fresh-VM installation when restoring a normal MyPaaS control-plane backup through the browser installer.

## Highlights

### Fresh-install control-plane restore

- The install wizard now restores the validated backup production `.env` before host preparation continues.
- The uploaded archive remains staged until deployment restores `database.sql` into the fresh control-plane PostgreSQL instance.
- The restored configuration is not appended a second time during deployment.
- Existing non-wizard staged-backup behavior remains supported.
- Backup extraction remains constrained to the validated control-plane archive contract.

The browser installer backup path restores the production configuration and control-plane database only. It does not restore project persistent volumes, static project artifacts, or Compose workspaces; use the full disaster-recovery workflow for those resources.

### mypaas-statd startup readiness

- Fresh installs now allow up to 15 seconds by default for `/run/mypaas/statd.sock` to become ready instead of a fixed two-second wait.
- The readiness loop exits early if systemd reports the service failed.
- Startup/readiness failures now print the service status and recent `mypaas-statd` journal entries so host-specific failures can be diagnosed directly.
