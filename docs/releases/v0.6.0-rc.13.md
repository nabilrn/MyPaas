# MyPaaS v0.6.0-rc.13

## Included changes

- Fixes 502 responses on `/api/*`, including GitHub login, after updating on rootful Podman/Netavark when the API container is healthy but its implicit control-network service alias is not usable after recreation.
- Pins explicit production control-network aliases for API, dashboard, Caddy, cloudflared, and PostgreSQL instead of relying on implicit Compose aliases.
- Preserves the shared PostgreSQL alias on the project network.
- Extends production verification to qualify `/api/health` and `/api/ready` through the same local Caddy ingress path used by browser API requests, so a healthy direct API IP can no longer hide a broken Caddy-to-API route.

## Qualification focus

Upgrade from rc.12 and confirm:

- the dashboard still loads through the Cloudflare Tunnel;
- `/api/auth/github/login` no longer returns 502 and reaches GitHub OAuth normally;
- `/api/health` and `/api/ready` succeed through Caddy;
- the API remains healthy on the control network;
- Docker and rootful Podman compatibility remain green;
- existing project routes and shared PostgreSQL access remain unchanged.
