# MyPaaS v0.6.0-rc.12

## Included changes

- Fixes release-update qualification on Podman/Netavark hosts when the MyPaaS API is healthy on the control network but the published `127.0.0.1:8080` forwarding path is stale or unavailable.
- Changes updater preflight to resolve the API address on the configured `CONTROL_NETWORK` and validate `/health` through that runtime path instead of treating the host-published API port as the source of truth.
- Changes production verification to use the same control-network API path for `/health`, `/ready`, and `/metrics`.
- Keeps stale project-network detection and control/project/routing network-isolation guards intact before any checkout or runtime mutation.
- Adds regression coverage preventing updater qualification from depending on `127.0.0.1:8080`.

## Qualification focus

Upgrade from rc.10 or rc.11 and confirm:

- a healthy API reachable through `mypaas-control` can qualify even when host loopback forwarding for port 8080 is unavailable;
- stale or missing project-network references still block safely before mutation;
- API health, readiness, and metrics verification succeeds through the control network;
- Docker and rootful Podman compatibility gates remain green;
- dashboard, Caddy, project routing, and existing workloads remain unchanged by this updater-only fix.
