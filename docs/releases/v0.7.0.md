# MyPaaS v0.7.0

**Release type:** Stable  
**Release date:** 2026-09-09  
**Release tag:** `v0.7.0`

`v0.7.0` establishes the first stable MyPaaS release line after the `v0.5.x` beta and `v0.6.0-rc.x` hardening series.

MyPaaS remains a **single-host self-hosted PaaS** for an owner developer or a small trusted team. This release does not introduce multi-node orchestration, automatic horizontal scaling, hostile multi-tenant isolation, or universal workload-capacity claims.

## Stable product surface

### Deployment

- Git repositories through Dockerfile, Docker Compose, or static output;
- OCI image deployment from compatible registries;
- GitHub repository picker and private-repository access for the connected administrator;
- repository inspection, base-directory/monorepo layouts, Compose detection/Doctor, environment discovery, and configuration checks;
- project lifecycle actions, deployment history, build/runtime logs, metrics, rollback, and route reconciliation;
- rootful Podman by default on fresh supported Linux hosts, with Docker Engine retained as compatibility mode through the Docker-compatible runtime contract.

### Routing and persistence

- Caddy-managed primary project routes;
- up to four bounded additional HTTP routes for Compose services using platform-derived hostnames;
- no generic raw TCP/SSH/UDP routing or arbitrary public port-forwarding surface;
- project-scoped persistent storage and owned-resource cleanup;
- optional shared PostgreSQL provisioning.

### Database Studio

DB Studio Lite supports:

- PostgreSQL;
- MySQL;
- MariaDB;
- eligible persistent SQLite databases.

The stable write boundary is intentionally narrow:

- read-only by default;
- temporary write sessions for validated primary-key row updates;
- insert and delete disabled;
- raw SQL disabled;
- persistent SQLite accepted only through the bounded persistent-mount/helper contract.

### Operations

- owner-only short-lived host shell;
- read-only host-wide container inventory with metadata-first loading;
- backup, restore, and migration tooling within documented boundaries;
- audit logs, CLI, REST API, GitHub webhooks, and the optional local MCP bridge;
- optional `mypaas-statd` host telemetry integration.

## Stable repository contract

The public repository now reflects the stable product boundary:

- README uses the official MyPaaS brand mark with Release, CI, and MIT License badges;
- current docs no longer present the product as Beta;
- current architecture/product/security docs are aligned with persistent SQLite and the update-only DB Studio contract;
- obsolete current-facing beta/planning residue was removed or reclassified as historical;
- public configuration examples are installation-neutral;
- public feedback is Issues-only through structured Bug report and Feature request forms; unsolicited pull requests are not part of the supported public contribution path.

## Upgrade note

Existing installations should continue using the normal MyPaaS update path. `v0.7.0` does not intentionally change deployment/runtime semantics relative to the final `v0.6.0-rc.16` product line; the stable preparation primarily aligns public contracts, documentation, support workflow, and release identity with the already-hardened implementation.
