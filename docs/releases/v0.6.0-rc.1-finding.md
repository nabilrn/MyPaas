# v0.6.0-rc.1 qualification finding

The first release-notification qualification exposed an API envelope parsing defect in the dashboard server route: `/auth/me` and `/settings` responses are wrapped as `{ "data": ... }`, while the route read them as unwrapped payloads. As a result, owner authorization resolved `role` as undefined and the notification surface returned `Status unavailable`.

This note records the RC finding only; the runtime fix is tracked separately.
