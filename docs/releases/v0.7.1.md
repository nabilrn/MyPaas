# MyPaaS v0.7.1

**Release type:** Stable patch release  
**Release date:** 2026-10-01  
**Release tag:** `v0.7.1`

`v0.7.1` is the first patch release on the stable `v0.7.x` line. It keeps the single-host trusted-operator product boundary while tightening release/update safety, improving GitHub-backed deployment recovery, expanding stable operator documentation, and simplifying host telemetry presentation.

## Highlights

### GitHub repository access and deployment recovery

- GitHub OAuth credentials can retain refresh metadata so expiring access tokens can be refreshed without forcing an interactive reconnect when a valid refresh path exists.
- Legacy stored GitHub access tokens remain readable.
- Repository discovery retries once through the refresh path after an authorization failure.
- Failed deployments now expose **Retry deploy** as the recovery action, including when a previous release is still serving traffic.

### Release and migration safety

- Stable release updates resolve the published GitHub release to a full Git SHA, verify the corresponding remote tag resolves to the same commit, and keep source plus immutable API/dashboard images on one release identity.
- Bootstrap accepts an exact 40-character Git SHA and uses a verified detached checkout for exact-revision installs.
- Migration destination instructions stay pinned to the installed platform revision instead of silently following the repository default branch.
- Migration restore no longer embeds the temporary migration download token in generated destination commands or installer argv; the token is consumed through protected input and the installer receives only a local archive path.

### Host resource telemetry

- The Projects host-resource area now combines RAM, CPU, and network history into one wider chart.
- Memory, CPU, and network lines can be hidden or shown independently without stopping telemetry collection.
- RAM and CPU retain percentage semantics; network keeps an adaptive rate scale.
- Successful telemetry outages are represented as gaps rather than fabricated continuity, and isolated samples remain visible.
- Storage remains a persistent horizontal capacity bar below the chart.

### Stable operator documentation

- Added and aligned stable installation, configuration, API, CLI, MCP, backup/restore, migration, update, uninstall, development, and production-verification documentation.
- Added deterministic CI guards for high-risk current public/operator documentation contracts.
- Stable backup/restore CLI and migration wording were cleaned up to match the current supported recovery contract.

## Release qualification

```text
74fb6a9d279148e32a54dec349d6f9ad84457ed0
```

The guarded release workflow requires this exact source SHA to remain current `main`, have a successful completed `CI` run, and have immutable API/dashboard GHCR images available before the GitHub release is created.

This patch does not change the stable product boundary: MyPaaS remains a single-host self-hosted PaaS for an owner developer or small trusted team, without multi-node orchestration, automatic horizontal scaling, or hostile multi-tenant isolation.

## Upgrade note

Existing stable installations should use the normal MyPaaS release-aware update path. The updater resolves the published release to its verified full Git SHA and waits for the immutable release images before changing the running installation.
