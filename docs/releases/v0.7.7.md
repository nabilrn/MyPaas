# MyPaaS v0.7.7

**Release type:** Stable patch release  
**Release date:** 2026-10-01  
**Release tag:** `v0.7.7`

`v0.7.7` fixes fresh-install statd readiness on non-root administrative accounts and makes interrupted browser-backup restores safe to resume.

## Highlights

### Correct statd readiness on root-owned runtime directories

- The installer now checks `/run/mypaas/statd.sock` through the existing privileged host helper.
- This matches the statd systemd contract: `RuntimeDirectory=mypaas` with mode `0750`, while keeping the socket local and root-owned.
- A healthy statd service is no longer reported as missing merely because the invoking non-root account cannot traverse `/run/mypaas`.
- `reconcile-statd.sh` uses the same privileged socket check.
- The secure runtime-directory permissions remain unchanged.

### Restart-safe fresh-install backup restore

- After the browser wizard applies the backup production `.env`, it now writes a private staged-restore marker.
- If installation is interrupted later, rerunning the installer detects that marker and resumes the staged control-plane database restore.
- The backup `.env` is not appended a second time on retry.
- The staged archive and marker are removed after the deployer consumes them.
- Legacy manually staged backups without the marker retain their previous behavior.

The browser installer backup path continues to cover the production configuration and control-plane database only. Full project persistent-volume, static-artifact, and Compose-workspace recovery remains part of the full disaster-recovery workflow.
